# 架构与上线手册

## 部署与账号

- Node.js 24.4 或以上。默认本地运行用 SQLite 和加密文件。正式部署用 `compose.yaml` 的 Postgres 与 Caddy，可用 S3 兼容对象存储替代本地附件卷。
- 将 `.env.example` 复制为 `.env`，填写 `RELAY_DOMAIN`、`RELAY_KEY`、`RELAY_USERS` 和 `POSTGRES_PASSWORD`。配置 DNS 指向网关并开放 HTTPS。数据库密码使用随机十六进制字符，保证 Compose 连接串直接可用。
- 在 PowerShell 运行 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成加密主密钥。每环境配置独立密钥。把密钥同数据库、附件备份分开管理。
- 通过安全的口令输入方式为临时环境变量 `RELAY_NEW_ACCOUNT_PASSWORD` 赋值，运行 `node scripts/hash-password.mjs` 得到 `passwordHash` 后清除该变量。按组织分配 `tenant`，每个 `id` 在本组织唯一，邮箱全局唯一，角色取 `owner`、`leaver`、`successor`、`hr`、`auditor`。
- 每个正式组织在 `RELAY_USERS` 配置至少一位 `hr` 作为引导账号。启动时按租户和账号 ID 导入新增条目，已导入的账号保留目录中的角色、密码与状态。人力资源在「组织与员工」中登记、开通、重置或停用员工。临时密码应通过安全渠道单独告知，员工改密后进入工作台。
- 已运行的组织可保留原有账号 ID 并补充 `hr`。如果所有人力资源账号都无法登录，部署管理员可用新的 ID 和邮箱引导一位人力资源账号，恢复管理后停用恢复账号。为演示和正式服务配置独立的数据库与密钥。
- 运行 `docker compose up -d --build`。网关转发时设置 `RELAY_TRUST_PROXY=1`，使应用正确校验来源。S3 配置存储桶、区域和凭证后，附件通过 SDK 读写，服务端先行加密。
- 配置 `RELAY_PAID_TENANTS` 为逗号分隔的付费租户标识。评分任务持久化，后台按优先级领取，付费租户任务先于试用任务，删除任务优先处理。验收页面显示预计等待时间。
- 探活 `GET /api/health`。使用正式账号验证 Secure 会话、创建岗位、导入 PDF、审计只读和跨租户拒绝。伪造或过期会话会被拒绝，退出会撤销当前会话。

## 数据与接口

`relay_records` 以 `(tenant, kind, key)` 为键。`position` 聚合保存岗位、按 ID 关联的资产与证据、材料元数据、访谈问答、验收卷与作答、报告版本、确认书、导出与删除任务。`workspace` 保存留存和月报审批。`session` 保存会话。`organization` 保存部门、员工和加盐密码散列。登录索引保存邮箱的带密钥摘要，用于按邮箱定位租户，和目录修改同事务提交。改密、重置、停用、变更邮箱或角色会撤销员工已有的会话。聚合更改通过事务提交版本和审计，Postgres 对同一聚合操作加行锁。

`relay_audit` 按组织追加操作、对象、操作者、时间、网络掩码、业务版本和少量运行元数据。数据库触发器拒绝修改或删除事件。职位记录和审计详情采用 AES-256-GCM，附件以租户路径和随机 ID 加密保存。报告版本生成后由验收记录追溯，三方签署各自绑定报告版本、时间戳和图像摘要。

| 请求 | 职责 |
|---|---|
| `GET /api/session`，`POST /api/session/login`，`POST /api/session/password` | 读取会话、正式登录、修改密码 |
| `GET /api/organization`，`POST /api/organization/departments`，`POST /api/organization/employees` | 人力资源查看和维护本组织部门与员工 |
| `GET /api/directory?departments=1` | 业务负责人和人力资源读取可用的岗位参与人和部门 |
| `GET /api/positions`，`POST /api/positions` | 总览与创建岗位 |
| `GET /api/positions/:id`，`GET /api/positions/:id/pack?q=词` | 岗位视图、交接包搜索 |
| `POST /api/positions/:id/:action` | 阶段操作及服务端授权 |
| `GET /api/positions/:id/exports/:exportId` | 下载经批准的版本 |
| `GET /api/audit`，`GET /api/audit?position=:id` | 审计视图、岗位记录 |
| `GET /api/settings`，`POST /api/settings/retention` | 审批、留存和人力资源运行看板 |

岗位操作映射在 `server/workflow.mjs`。JSON 错误包含可操作的 `error` 文案。岗位不存在或跨租户访问返回 `404`，角色不符返回 `403`，阶段冲突返回 `409`，忙碌返回 `429`。闭卷阶段服务端关闭资产明细、历史报告证据和导出访问。审批申请绑定快照，申请人与审批人需分开。

## 模型与质量门禁

- `RELAY_AI_ENDPOINT` 填写支持结构化聊天补全的完整接口，配套设置 `RELAY_AI_API_KEY`、`RELAY_AI_MODEL` 和每百万令牌的人民币价格。支持 `json_schema`，部分提供方可配置 `RELAY_AI_JSON_OBJECT=1`。
- 公开级材料仅在参与者单独授权后才进入模型流程，传输前处理常见个人标识。S2 进入本地流程，S3 仅保留访问路径。截图提交人需确认已移除高危内容，截图内的文字需要人工核对。
- `server/ai.mjs` 保存抽取与评分的提示及 Schema。材料与访谈建议需核对原文，低置信结论进入人工队列。评分抽检至少 20%，全部待复核题处理完才能生成正式报告。费用与令牌达到 50 元或 350,000 的预算边界时走规则与人工流程。
- `npm run evaluate -- path/to/golden.json` 接受脱敏标注样本数组。每项提供 `name`、`text`、关键资产标题 `expected`，可选提供 `grading` 数组，每条包含 `terms`、`answer`、人工分类 `human`。从原文逐条标注关键项，两位复核人共同确认题目可用性和评分依据。保留真实基线，用 PRD 的召回、编造率、P95 和成本门禁决策。
- `npm run gate -- current.json baseline.json` 校验绝对门槛及基线变化。两个文件使用同一标注集、负载和模型成本口径，指标包括 `criticalRecall`、`ungroundedRate`、`questionUsability`、`kappa`、`p95Ms`、`cost`、`failureRate`。比例按 0–1 录入、耗时以毫秒计、成本以元计。

## 监控、恢复与客服

1. 用定时探活检查 `/api/health`。人力资源登录后可查看近 24 小时各阶段的耗时、模型费用、令牌和重试等指标。命中样本汇总的异常岗位占比超过 2%、阶段 P95 超相应目标 20%、单岗位模型费用超过 80 元或本组织队列积压超过 50 项会显示告警。上线时配置值班系统读取 `GET /api/settings` 的 `monitor.alerts` 字段。缓存命中率需要模型返回缓存用量。过期评分执行租约可由后台重新领取。
2. 扫描件、加密文件和解析超时可粘贴正文并补来源。模型失败保留降级记录，使用模板和人工复核推进。P0 优先暂停数据流入和导出，值班人记录影响范围并通知负责人。
3. SQLite 使用 `npm run backup -- <目标目录>` 做在线数据库快照。包含本地附件的备份在维护窗口停止写入后执行。恢复时配置独立 `RELAY_DATA` 目录，复用原加密密钥，核对报告、附件、签名和审计可读性。
4. Postgres 使用 `pg_dump --format=custom`、加密附件卷快照或 S3 备份。每日全量、每小时增量，恢复目标为 RTO 4 小时及 RPO 1 小时。正式验证在隔离环境按同一备份点恢复数据库与附件，演练回滚到上个镜像和模型配置。
5. 留存默认归档后 24 个月，可按组织调整。审批删除后马上停止岗位访问，后台清除记录及附件，留存最小审计记录。归档与备份清理按处理协议执行，恢复后的存储须重新执行删除清单。
6. 工单 4 小时内响应，P0 在 1 小时内升级给值班工程负责人和组织数据负责人，随严重程度升级至法务与业务负责人。灰度按 PRD 进行 10% 租户 24 小时观测，回滚目标 5 分钟。
